# 资产全景 2.0

个人用、只在 iPhone（主屏幕 PWA）上使用的月度资产看板。每月记录一次各账户余额，自动算总资产、配置、变化，以及**工资对应的本月净开销**。

旧版 `niupipiii/my-assets` 是单文件 React + localStorage；这一版改成 Vite + React 19 + TypeScript 的 PWA，数据仍然只存在本机浏览器。

## 功能

- 月度资产快照：5 个主分类（现金 / 储蓄 / 理财 / 基金 / 股票）+ 任意子账户，按月记录余额，自动带出上月值。
- 默认账户结构：微信零钱 / 农行现金 / 中行现金 / 招行现金；余额宝 / 招行储蓄；农行理财 / 招行理财 / 中行理财；基金；股票。旧分类仍保留给历史数据。
- 总览：总资产、环比、12 个月趋势、**只展示 5 类的资产配置**、本月变动 Top。
- 资产配置只画 5 个主分类；旧分类（房产/保险/数字货币/其他）如果还有余额，会合并成「其他」，不会从总资产里消失。
- **工资与净开销**：每月工资可单独覆盖；按公式推导本月消费净开销，并展示完整拆解。
- 报表：月度/年度、净开销趋势、**一级账户月度构成 100% 堆积图（按一级账户看占比变化）**、一级账户余额绝对值折线图（可点击图例筛选）、可分享的月报图片。
- 明细：全文搜索、分类/标签筛选、月度详情、编辑/删除。
- 账户：新增、改名、机构、标签、备注、排序、归档；改名不影响历史。
- 截图识别：上传银行/微信/支付宝截图，由云端视觉模型读取余额，人工确认后填入。
- PWA：离线可用、可添加到主屏幕、自己检查更新；数据不上传服务器。
- 数据安全：旧键永不删除、首次迁移前自动备份、每日自动快照、JSON/CSV 导出导入。
- **整数金额**：界面显示与保存都四舍五入为整数；旧版小数迁移时也取整，但下载的原始 JSON 保留小数。

## 本地开发

```bash
cd my-assets
npm install
npm run dev          # http://127.0.0.1:5173
npm run build        # tsc + vite build
npm test             # Vitest 单元测试
npm run preview      # 预览生产构建（含 PWA / Service Worker）
```

- Node 20.19+（当前机器 20.20 可用）。
- 开发时打开 `http://127.0.0.1:5173/?preview=1&demo=1` 会加载演示数据，方便看空状态以外的界面；`?preview=1` 还会启用安全区模拟。
- 生产构建的离线行为可以用 `npm run preview` 验证（Service Worker 只在生产构建里启用）。

## 数据与迁移

旧版数据键（**不会删除**）：

- `asset-records`：`[{ year, month, ts, assets: { [category]: { [accountName]: number } } }]`
- `asset-config`：`{ subAccounts: { [category]: string[] } }`

新版：

- `myassets:v2:ledger`：规范化后的账本（账户、快照、每月现金流、设置）。
- `myassets:v2:ocr-token`：截图识别的访问口令（不进导出）。
- `myassets:v2:backup:*`：自动/手动备份，最多 8 份。
- `myassets:v2:legacy-copy`：迁移时保存的旧版原始副本。

迁移流程：

1. 同一域名下打开新版，启动时检测到旧版数据。
2. 弹出「发现旧版数据」，显示月份数、账户数、最新总资产。
3. 点「开始迁移」后：先保存原始旧版 JSON → 写一份迁移前备份 → 转成正式账户和快照。
4. 迁移完成后显示核对卡；旧版键仍然在，可随时导出。
5. 迁移后建议到「设置 → 账户管理 → 补齐默认账户」创建缺失的默认账户；旧账户可以归档，历史仍保留。

如果域名或 origin 变了（例如换成了另一个 Vercel 项目），旧数据读不到。部署新版后可以打开 **`/legacy-export.html`** 在同域名下查看旧数据、下载原始 JSON；这个页面只读，不修改数据。

## 工资与净开销

设上月末总资产 `A₋₁`、本月末 `A`，`Δ = A − A₋₁`；投资类资产变化 `ΔInv`；本月净转入投资 `T`；投资收益 `R`；其他收入 `OI`；其他流出 `OO`；工资 `S`；消费净开销 `C`。

```text
R = ΔInv − T
Δ = S + OI − C − OO + R
C = S + OI + R − Δ − OO
```

默认投资类别：股票、基金、理财。现金、储蓄、房产、保险默认不计入（不做月度市值重估）。

示例：

- 工资 20,000；投资类 300,000 → 303,500；总资产 1,000,000 → 1,018,200；无转入
  → 投资收益 3,500，净开销 **5,300**
- 同上，但本月净转入投资 2,000
  → 投资收益 1,500，净开销 **3,300**
- 同上（无转入），把本月工资单独改成 25,000
  → 净开销 **10,300**（不是 8,300；`25,000 + 3,500 − 18,200 = 10,300`）

买入/卖出股票、基金时，一定要在「本月工资与调整 → 净转入投资」里填写，否则这笔钱会被算成净开销或收益。所有数字都可以在「本月推导」里逐项核对。

## 截图识别（云端）

客户端把截图压到最长边 2048、JPEG 0.85，再 POST 到同域名的 `/api/ocr`；服务端用 OpenAI 兼容的视觉模型解析，返回结构化余额。截图不落盘、不写日志。

- 最多一次 **20 张**截图；可以分批识别。
- 识别时**优先取分类合计**：例如资产负债表里的「活期 8,855.09」「理财 42,365.54」，不会把下面的三只理财产品和总资产 51,220.63 一起返回。
- 六类固定截图按页面结构自动识别来源，不需要手动选账户：
  - 东方财富：股票 → 一条“股票”＝总资产
  - 中国银行：“活钱管理 / 稳健投资” → 中行现金 / 中行理财
  - 招商银行：“账户总览 / 活钱 / 存款 / 理财” → 招行现金 / 招行储蓄 / 招行理财
  - 微信：零钱 → 微信零钱
  - 支付宝：余额宝 / 基金 → 余额宝 / 基金
  - 中国农业银行：活期 / 理财 → 农行现金 / 农行理财
- 固定结构漏项时（例如招商偶尔漏掉“存款”），服务端会针对漏项再提取一次，不需要你手动补。
- 返回的 `section` 会和机构一起映射到默认账户；微信零钱通不足 1 元时会被整数规则四舍五入为 0，不再计入。
- 没有匹配到已有账户时，确认界面会给出「新建账户「农行现金」」按钮，直接按默认结构创建。
- 金额入库前统一四舍五入为整数。

Vercel 环境变量：

```text
OCR_VISION_BASE_URL   例：https://api.deepseek.com
OCR_VISION_API_KEY    供应商 Key（不要提交到 git）
OCR_VISION_MODEL      例：deepseek-flash / gemini-2.5-flash / gpt-4o-mini
OCR_ACCESS_TOKEN      你自定义的访问口令，App 设置里填同一串
```

- **DeepSeek 开放平台已实测可用**：`OCR_VISION_BASE_URL=https://api.deepseek.com`、`OCR_VISION_MODEL=deepseek-flash`，`deepseek-flash` 支持图片输入；`deepseek-v4-pro` 是纯文本，不适合 OCR。
- API Key 只在 Vercel 环境变量里；`OCR_ACCESS_TOKEN` 只是防止公开接口被陌生人盗刷。
- 本地联调：把同名变量放进 `.env.local`（已在 `.gitignore` 中），Vite 开发服务器会通过内置的 `/api/ocr` 中间件调用 `api/ocr.ts`。
- 没有口令/接口未配置时，识别页会提示；开发环境还有一个「用示例结果预览确认界面」按钮（只用于检查确认 UI，不会上传）。
- 真实识别准确度依赖模型；识别结果必须人工确认后再保存。

## iPhone 预览插件（DSH）

插件源码在同级目录 `../iphone-preview`，已安装到当前 `desktop` profile：

- 输入区的手机图标：打开/聚焦右侧栏「iPhone 预览」。
- 右侧栏指南 → 更多工具 → iPhone 预览：同样可以打开。
- 默认机型 **iPhone 14（390×844，刘海，47/34 安全区）**；可切换 15/16 Pro/Max、SE。
- 开发/线上源切换、深浅色、刷新、1:1/适应、地址设置、演示数据。
- 开发源走 Vite HMR，改代码约 1 秒更新；状态点显示开发服务器是否在线。
- 预览 iframe 是第三方上下文，浏览器会隔离其 localStorage，所以默认加载演示数据；真实数据请在手机主屏应用里看。

安装后需要**刷新一次 DSH 页面**加载新的客户端模块。如果面板没出现，先确认 `npm run dev` 正在运行，然后从右侧栏指南打开；仍不行时，用内置右侧栏 Browser 打开 `http://127.0.0.1:5173/?preview=1&demo=1` 作为回退。

## 部署（上线前先本地验收）

新版必须继续部署在**同一个 Vercel 项目和域名**（当前 `https://my-assets-three.vercel.app`），这样 iPhone 上的旧 `localStorage` 才能原地沿用。

1. 提交并推送到 `main`；Vercel 自动构建。
2. Vercel 项目设置：Framework 选 Vite（或在 `vercel.json` 已固定），Build Command `npm run build`，Output `dist`。
3. 在 Vercel 配置上面的 4 个 OCR 环境变量。
4. 上线后检查 `/version.json` 的 buildId 已更新；手机打开 `/legacy-export.html` 核对旧数据；再打开 `/` 迁移。
5. 回滚：Vercel Instant Rollback 到上一部署，或 `git revert`；旧数据键不受影响。

当前环境没有 GitHub 凭证，`git push` 会要求登录；部署时需要在有 GitHub 权限的终端执行，或先 `gh auth login` / 配置 PAT。

## 已知限制

- 数据只在当前浏览器/设备；换手机、清网站数据会丢，务必用导出/备份，或把 PWA 添加到主屏幕降低被清理概率。
- 仍是「每月余额快照」，不是逐笔收支流水；净开销是推导值。
- 投资收益是估算，依赖你如实填写转入/转出。
- Chromium 里的 iPhone 预览不等于 WebKit 真机；状态栏、安装行为是模拟，最终以 iPhone 14 实机为准。
- 云端 OCR 需要网络和 API Key；截图会上传到模型供应商。
